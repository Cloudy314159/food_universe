### 异常路径（Day 18 / Day 19 已验证，回归时复测过）

| 场景 | 期望 | 实测 |
|---|---|---|
| 同一条重名再提交 | `409 DUPLICATE_NAME` + 中文提示 | ✅ |
| 缺 `name` 字段 | `400 INVALID_NAME`「缺少必填字段：name（名称）」 | ✅ |
| `type` 传非法值 | `400 INVALID_TYPE` | ✅ |
| 请求体不是合法 JSON | `400 INVALID_BODY` | ✅ |
| 不存在的路径 | `404 NOT_FOUND` | ✅ |

**为什么重名要单独测**：它走的路径最长（应用层放过 → 数据库报错 → 网关包装 → 接口翻译回中文）。
Day 18 第一次跑时正是这里翻车 —— 网关把 SQLSTATE 包成了 `DATABASE_23505`，
接口层只认裸的 `23505`，结果返回了 500 而不是 409。**错误路径必须真跑一遍。**

| **数据访问层** | `repositories/client.js`、`itemsRepository.js`、`historyRepository.js` | **13** | 全在这里 ✔ |

### 行为有没有变（这才是重点）

Day 19 做过一次 **10 条用例的回归**，做法比截图硬：

- 重构**前**跑一遍，把每个接口的**完整原始响应**存进 `_day19/baseline.json`
- 重构**后**再跑一遍，存进 `_day19/after.json`
- 脚本逐条比**形状**（HTTP 状态 / `ok` / `error.code` / `data` 的键 / 行字段）

**结果：10 / 10 完全一致。**

> ⚠️ 对比时**故意不比自己会变的值**（`id`、时间、`total`）—— 拿它们比必然"不一致"，
> 那是**假失败**。只比结构才说明"行为没变"。
