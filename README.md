- **Node.js 18 或更高**（本项目在 **Node 22.22.2** 上开发并验证）

```bash
node -v
npm -v
```

两条都打印出版本号就说明没问题。没装的话去 <https://nodejs.org> 下 LTS 版。


| # | 查什么 | 怎么算通过 |

| 4 | 硬编码密钥 | 当前代码 + Git 全部历史都 0 命中。只扫被 git 跟踪的文件，**避开含真 Key 的部署配置** |
| 5 | 忽略规则 | `.env` 被忽略、`.env.example` 存在且没有真值、仓库里只有 `.env.example` |
| 6 | 数据库 | `items` / `history` 两张表都能读出真实行（不直连库，不碰凭据） |

在对话里也可以直接说「跑一下发布前检查」。

## 数据存在哪

⭐ **Day 17 起，数据存在云上的数据库**（CloudBase PostgreSQL），前端通过
`/api/items` 和 `/api/history` 两个接口取数。

**浏览器本地还留着一份 localStorage 当缓冲**（`src/lib/storage.js`）：
打开页面时先把云上的数据拉下来灌进去，之后页面照旧从它读。
这么做是为了**页面代码一行都不用改** —— 「数据从哪来」被挡在了数据层里面。

所以现在的行为变了：

- 换个浏览器、换台电脑 → **看到的是同一份数据**（都在云上）
- 清浏览器缓存 → **数据不会丢**（下次打开重新从云上拉）
- ⚠️ **但写入操作（添加 / 删除）当前还只改本地** —— 写入接口是 Day 18 的事，
  在那之前自己加的条目还上不了云

三个存储键（仍是本地缓冲用的键名）：

| 键 | 存什么 |
|---|---|
| `chisha:items` | 清单条目（云端拉下来的 + 本地自己加的） |
| `chisha:filter` | 过滤条件（**这个是纯本地的偏好，不上云**） |
| `chisha:history` | 历史记录（最多 20 条） |

## 四种页面状态怎么看

⭐ **Day 17 起，四种状态全都会自然发生** —— 数据源从浏览器本地换成了云上的数据库。
（Day 13 起「我的清单」和「历史记录」也有这四种状态了 —— 四个页面同一套。）

| 状态 | 什么时候出现 | 怎么看到 |
|---|---|---|
| 成功 | 有候选，正常显示 | 直接打开页面 |
| **空** | 候选为 0：清单被删光，或过滤条件把候选全排除了 | 去「我的清单」把条目删光，再回首页 |
| **加载中** | **打开页面时正在向服务器取数**（本地网络约几百毫秒） | 正常打开页面，它会闪一下 |
| **错误** | **取不到**：断网 / 接口挂了 / 超过 8 秒没回应 | **把网络断掉再打开**；错误页上有「重试」和「先用缓存看」 |

**为什么现在能自然发生了**：Day 13 写这两个状态的时候，数据全在浏览器本地、**同步读**，
既没有"等待"也没有"请求失败" —— 它们**物理上不可能发生**，只能靠参数人工调出来看一眼。
那时留下的注释是「给第 3 周接真实接口预留的位置」。**今天接口接上了，它们自己就长出来了，
样式和文案一个字没改。** 那句"预留"，预留的就是今天。

**怎么进这个开关**：地址栏加 `?demo=正常｜空｜加载中｜错误`（例如 `?demo=loading`）→
页脚就会出现一个「状态演示」下拉，点一下换一种状态，四个页面都吃这一套。

**怎么退出**：点下拉旁边的「退出演示」，或者把地址里 `?demo=…` 这段删掉再回车。

⚠️ **客户看不到这个开关** —— 下拉只在地址带 `?demo=` 时才渲染，
正常访问产品时页脚只有那句数据说明。

**关于「空」状态的一个提醒**：开发的时候手上永远有那 50 条内置数据，**你永远看不到空**；
但真实的新用户第一次打开、或者把清单删光时，它就是空的。所以这一种最容易被忽略——
而它恰恰是用户最需要引导的时候。

## 遇到问题

**装依赖很慢或者失败**
换国内镜像再试：

```bash
npm install --registry=https://registry.npmmirror.com
```

**页面是白屏 / 某块不显示**
按 `F12` 打开开发者工具，点 `Console` 看有没有红色报错。有的话把红色那几行记下来。

**想从头来一遍（清空所有数据）**
按 `F12` → `Application` → 左侧 `Storage` → `Clear site data`，然后刷新页面。
清单会被重新播种成内置的 50 条。

**「换一个」换不动了**
如果清单里只剩 1 个条目，页面会提示「现在只有 1 个可选」——这是设计如此，
不是坏了。去「我的清单」加几条，或者点「恢复默认库」。
